<objective>

Purpose: This is META-01's runtime. It honors every locked decision: D-01 (outbound-POST Bearer endpoint, fail-closed), D-02 (deterministic no-model dedupe within the tool bucket, KV threshold, borderline→keep-separate+Flagger), D-03 (Haiku derivation, stable slug), D-04 (re-save overwrites + bumps uses on the same slug), D-05 (append-only). Pillar 1 holds: producer only, NO new atlas-wire consumer.
Output: A complete `apps/librarian/` Worker (source + config). Tests land in 05-03.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local daemon / external caller → `POST /prompt/save` | Untrusted inbound HTTP crosses into a Worker that writes D1 + emits Vault writes |
| `full_prompt` body → Wire payload → Steward → Vault | Owner-written prompt text becomes a note body sent over the 128KB-capped Queue |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-Auth | Spoofing | POST /prompt/save Bearer gate | mitigate | `timingSafeEqual` (HMAC-SHA-256, fresh key, length-independent) from `@atlas/gate`; `ATLAS_LIBRARIAN_TOKEN` async Secrets Store binding; fail-closed (401) on wrong/missing token AND missing binding; auth before body parse. Task 1 + 05-03 failure tests. |
| T-5-DoS | Denial of Service | inbound body size | mitigate | zod validation + 50KB soft limit on `full_prompt` (rejected with P3 flag, no Wire emit) — stays well under the 128KB Queue cap that `send()` enforces. Task 3. |
| T-5-Tamper | Tampering | notePath in emitted payload | mitigate | Librarian always sets `notePath="Prompts/<slug>.md"`; the central `toOutboxIntent` constraint (05-01) rejects any non-Prompts path with NonRetryableError — defense in depth (Librarian + Steward). |
| T-5-Info | Information Disclosure | token / prompt content in logs | mitigate | Bearer token never logged and never written to any D1 row; `audit_log.scope_used=''` for Librarian (no OAuth scope). `full_prompt` is owner-written — documented in the runbook (05-04) that the owner must not save secrets; no automated stripping needed (unlike Herald email bodies). |
| T-5-Pillar1 | Elevation of Privilege | wrangler.jsonc queues | mitigate | Producer-only `queues.producers`; NO `consumers` block; guard-wire-consumer.js verifies. Steward remains the sole atlas-wire consumer. Task 1. |
| T-5-Replay | Tampering | idempotency key | mitigate | Structured stable keys (`librarian:<slug>:save` / `:save:<date>`); never `crypto.randomUUID()`; replay through Steward = `meta.changes===0` (proven in 05-03). A bump is an upsert on the SAME slug — no clone, no double-count of `uses`. |
| T-5-SC | Tampering | npm/pip/cargo installs | mitigate | No new external packages (RESEARCH Package Legitimacy Audit: none). Only workspace deps (`@atlas/*`) + existing devDeps. No install task. |
</threat_model>
