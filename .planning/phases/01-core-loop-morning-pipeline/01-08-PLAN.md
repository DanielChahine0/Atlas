<objective>
Wire the five Phase-1 agents into ONE durable Cloudflare Workflow. Add `MorningChain extends WorkflowEntrypoint` to the Atlas Worker with five `await`ed `step.do` steps (Filer→Herald→Forge→Sundial→Compass) gated by `step.sleepUntil` budget gates; the `invokeAgent` service-binding RPC transport (Phase-0 D-11) that each step uses; the `localTime(date,"HH:MM",tz)` DST-safe helper; the 07:45 cron case in the dispatcher that creates the instance with `id: morning-${date}`; the halt→Flagger P2 emission; and the go-live checklist capturing the three owner gates (D1-03 baseline, D1-04 miss-review affordance, D1-06 gateway ceilings). This plan closes CORE-01 — the strictly-sequential, resume-on-failure, halt-downstream, idempotent-on-re-fire chain.

Purpose: the Workflow is the crux of the phase — `await` gives start-after-success, step memoization gives resume-on-failure, an exhausted-retry step errors the instance and halts downstream, and the instance id makes a re-fire a no-op. Five racing crons would have none of these properties.
Output: the MorningChain Workflow + dispatcher case + invokeAgent transport + the chain crux tests + the go-live checklist.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cron → Workflow | The cron only triggers; the Workflow owns durable sequencing. A re-fire/missed-then-recovered cron must be safe (idempotent). |
| Workflow step → agent (service-binding RPC) | Worker-to-Worker RPC, no public HTTP; each step passes the prior step's return forward (never mutates event.payload). |
| Halted instance → Flagger | A halt must surface exactly one P2 incident, never silently drop. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-CHAIN-01 | Availability | step failure | mitigate | await-ed steps + per-step retries; an exhausted-retry step errors the instance → Sundial/Compass never run on stale data (halt-downstream); upstream side effects stand. |
| T-1-CHAIN-02 | Repudiation / duplicate runs | re-fire | mitigate | instance.id = morning-${date} → re-fire is a no-op; Steward dedup makes replayed emits no-ops; a missed cron is caught by the next idempotent run. |
| T-1-CHAIN-03 | Tampering (replay state) | step payload | mitigate | Steps return state forward; event.payload is never mutated inside a step (reverts on replay). |
| T-1-CHAIN-04 | Detectability | halt emission | mitigate | A halted instance emits exactly one chain.halted P2 (idempotencyKey morning-halt:<date>:<step>); never a silent drop. |
| T-1-COST-02 | Resource exhaustion (cost) | Filer push | mitigate | D1-06 owner gate — push stays off (filer.push_enabled=false) until AI-Gateway ceilings are set in the dashboard. |
| T-1-SEC-SC | Tampering | npm installs | accept | No new package installs (RESEARCH Package Legitimacy Audit). |
</threat_model>
