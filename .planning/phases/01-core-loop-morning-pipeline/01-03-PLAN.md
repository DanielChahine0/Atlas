<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gmail threads → Filer (untrusted email content) | Email bodies may carry 2FA codes / reset links / phishing payloads; Filer reads + labels only and must never surface or act on them. |
| Filer → Gmail (label mutation) | The only permitted mutation is label add/remove; delete/archive must be unreachable. |
| Filer → Wire → Steward | The emitted counter event must be replay-safe (structured idempotencyKey). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-SEC-01 | Information Disclosure | sweep classification output | mitigate | Type/Security + Phishing-Suspect read-and-label only; bodies redacted server-side (mcp-google); no code/link reproduced in any label or emitted payload. CI security.test.ts backstops. |
| T-1-SEC-02 | Elevation/Tampering | Gmail mutation surface | mitigate | gmail.modify scope only; no delete/archive/trash tool bound (unreachable by construction, Pillar 2); reserved system labels never written. |
| T-1-SEC-03 | Spoofing (phishing) | ⚠ Phishing-Suspect handling | mitigate | A phish thread gets NO Needs/* or Suggest/* label and no clickable link — the owner is never nudged to act. |
| T-1-SEC-04 | DoS / cost | continuous push path | mitigate | Push path flag-gated off (filer.push_enabled=false) until D1-06 gateway ceilings are set; sweep uses backoff-with-jitter on 429/403. |
