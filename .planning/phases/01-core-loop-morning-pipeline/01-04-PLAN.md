<objective>
Build Herald (`apps/herald`) — the daily email digest. One new Worker exposing a `daily` RPC method (the `herald-daily` Workflow step's target) that reads Filer's labeled threads in the 24h window, buckets them into the five owner-requested sections, redacts security mail, synthesizes a digest body, creates a Gmail DRAFT to the owner (never sent), and emits a `digest` Wire event for the Vault morning-glance. Herald holds `gmail.readonly` + `gmail.compose` only — it never labels, sends, or deletes. The non-negotiable security guardrail: 2FA codes / reset links / login URLs NEVER reach the output; if the guardrail trips on the OUTPUT, the draft is blocked and a P2 raised.

Purpose: the digest is the owner's morning glance and the single most owner-visible artifact of the MVP; its security invariant (no secrets surfaced) is a hard pillar. Per D1-01 keep the Gmail draft AND emit the digest event; per D1-02 run daily every weekday with no Friday special-casing.
Output: the `apps/herald` Worker, the bucketing + guardrail modules, and the three DoD tests (section order, Wire-contract, redaction).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gmail threads (incl. Type/Security) → Herald | Email content may carry 2FA codes / reset links; Herald processes the whole inbox so it is a prime leak site. |
| Herald → Gmail draft + digest event | The draft and the Vault digest are owner-visible outputs; a secret must never reach either. |
| Herald → Gmail (write surface) | Herald may only create a DRAFT — never send, never label, never delete. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-SEC-05 | Information Disclosure | digest synthesis output | mitigate | Pre-synthesis strip of code tokens + reset/login URLs; OUTPUT-side containsSecret() guardrail blocks the draft + raises P2 on any leak (defense-in-depth atop mcp-google server-side redaction + CI test). |
| T-1-SEC-06 | Tampering / outward action | Gmail write surface | mitigate | gmail.compose = draft only; NO send tool registered (Pillar 2); Herald cannot send or label. |
| T-1-SEC-07 | Spoofing (phishing) | ⚠ Phishing-Suspect rendering | mitigate | Phishing threads under Other with a visible warning and NO clickable link — never under Important/Action. |
| T-1-SEC-SC | Tampering | npm installs | accept | No new package installs (RESEARCH Package Legitimacy Audit). |
</threat_model>
