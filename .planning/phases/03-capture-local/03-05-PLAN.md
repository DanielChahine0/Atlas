Core Audio process tap (RESEARCH Pattern 4 + Pitfall 1; ref github.com/insidegui/AudioCap):
  CATapDescription(stereoGlobal: true) -> AudioHardwareCreateProcessTap(tapDesc, &tapID)
  -> AudioHardwareCreateAggregateDevice([kAudioSubTapUIDKey: uuid, kAudioAggregateDeviceIsPrivateKey: true])
  -> AudioDeviceCreateIOProcIDWithBlock(...). Silent-zeros watchdog: if buffer RMS < 1e-7 for > 500ms
  while output is running, tear down + recreate BOTH the Process Tap AND the Aggregate Device (partial
  teardown is unreliable) and raise a P3 via IncidentRelay.

Two-channel diarization (D3-06; RESEARCH Pattern 5 + Pitfall 6):
  mic channel -> hardcoded "Owner" (deterministic, free). loopback channel -> FluidAudio
  LSEENDDiarizer (DiarizerModels.downloadIfNeeded(); 16 kHz MONO Float32 — resample via AVAudioConverter
  from the device's native 44.1/48 kHz stereo). segment.confidence < 0.6 -> keep as "Speaker N" + flag P4
  (never drop). WhisperKit transcribes both channels (argmax-oss-swift v1.0.0, model large-v3-turbo).

Consent state machine (D3-10, D3-11, D3-12; RESEARCH Pitfall 3):
  IDLE -> ARMED (indicator shown, consent prompt displayed, NO WS open, NOTHING captured)
       -> ACTIVE (owner clicks Start -> WS opens -> capture starts).
  Decline -> consent:"discarded", NOTHING persisted (no D1 meetings row, no transcript), P3 logged.
  v1 live UI = the non-dismissable indicator (menubar dot + "Echo is capturing") + pause/stop + the
  consent prompt + a one-click logged "this call may be recorded" announce helper. No live transcript window.

EchoSession WS client (the 03-02 cloud contract):
  getByName name = "echo-<ISO-timestamp>" (stable; the daemon connects to wss://.../?session_id=echo-<ts>);
  reconnect uses the SAME name -> same DO -> resume from the local buffer + the DO's stored segments;
  ping/pong handled by the DO's setWebSocketAutoResponse. On meeting end: write the transcript JSON, request
  a presigned PUT for transcripts/<session_id>.json (always) and audio/raw/<session_id>.opus (ONLY if
  audio_disposition == "r2-approved" — per-session owner approval; default local-only), upload DIRECT
  (never proxied), then emit the transcript.ready Wire event (key echo:<session_id>:ready) via the outbound
  channel.

EventKit auto-arm (Open Question — EventKit recommended):
  EKEventStore + EKAuthorizationStatus.fullAccess; watch EKEventStoreChangedNotification; events with
  hasVideoConference/videoConferenceURL are the primary arm trigger; audio-active is the ad-hoc fallback.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| meeting audio -> on-device pipeline | Raw audio must be processed on-device; only a derived artifact may leave |
| daemon -> EchoSession DO (WS) | Outbound stream of diarized segments to the cloud |
| daemon -> R2 (presigned PUT) | Direct audio/transcript upload; gated by per-session approval |
| consent prompt -> capture | The single point that authorizes any retention |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05-01 | Information Disclosure | audio captured/streamed before consent | mitigate | IDLE->ARMED->ACTIVE state machine: ARMED opens NO WS + captures nothing; WS open is physically unreachable except from the consent-confirmed handler (Pitfall 3); ConsentGateTests asserts it |
| T-03-05-02 | Repudiation | a meeting recorded without a defensible consent record | mitigate | Per-session owner Start attestation + a logged "announce" helper (D3-10); decline -> consent:"discarded" + P3 so the run-log shows a contentless meeting; consent capture = 100% (gating) |
| T-03-05-03 | Information Disclosure | raw audio leaving the device without approval | mitigate | audio_disposition default "local-only" (transcript is the artifact); audio/raw/ presign minted ONLY when "r2-approved"; direct upload, 7-day lifecycle on audio/raw/ (D3) |
| T-03-05-04 | Tampering (data integrity) | silent-zeros tap producing an incomplete transcript | mitigate | RMS watchdog -> destroy+recreate BOTH tap AND aggregate device + P3; partial transcript flagged incomplete in the note (Pitfall 1) |
| T-03-05-05 | Spoofing | stale EchoSession WS reused after the meeting ended | mitigate | reconnect uses the same getByName name; the DO's finalize marks the session terminal (03-02 T-03-02-01); a post-finalize WS cannot mutate the frozen transcript |
| T-03-05-06 | Information Disclosure | low-confidence speaker split silently dropped (data loss) | mitigate | confidence < 0.6 splits are KEPT as "Speaker N" + flagged P4 and surfaced for an Archivist "correct the speakers" step — never silently dropped (D3-06) |
</threat_model>
