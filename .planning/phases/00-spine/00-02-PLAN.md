<!-- The §6.4 Wire contract this plan DEFINES (build-plan §5.1 lines 1198-1206 / SPEC §6.4). -->
<!-- Authoritative shape — every later plan imports this from packages/wire, no re-definition. -->

WireEvent (packages/wire/src/contract.ts):
  agent:          z.string()                                  // roster codename: "Atlas" | "Forge" | "Filer" | ...
  type:           z.string()                                  // e.g. "noop.tick", "task.created", "flagger.incident"
  entity:         z.string()                                  // logical target, e.g. "tasks", "spine", "flagger"
  op:             z.enum(["increment", "upsert", "append"])   // increment→counters | upsert→stable rows | append→feeds
  payload:        z.record(z.unknown())
  idempotencyKey: z.string().min(1)                           // STABLE + structured, never crypto.randomUUID()
  type WireEvent = z.infer<typeof WireEvent>

The canonical Flagger Wire event (SPEC-CANON §8 + docs/08-flagger.md §6/§7/§14 — supersedes the stale
build-plan §"Observability" line 1269 stub) — what flag() must build:
  { agent: <emitter codename>, type: "flag", entity: "flag", op: "upsert",
    payload: { id, ts, source_agent, severity, trust, title, detail, suggested_action, status },
    idempotencyKey: <flag.id> }
  -- a flag is a STABLE ROW keyed by `id`, mutated in place (status open→ack→resolved) ⇒ op:"upsert"
  -- payload.status starts "open"; payload.source_agent === top-level agent (the emitter)
  -- idempotencyKey === payload.id, a STRUCTURED id (e.g. flg:<localDate>:<source_agent>:<contentHash>),
     NEVER crypto.randomUUID() — a replay re-upserts the same row ⇒ no duplicate board row
  severity ∈ "P1" | "P2" | "P3" | "P4"   (deterministic by source signal, not LLM)

D1 run_log §5.2 superset columns (from migrations/0001_init_core.sql, owned by 00-01):
  id (AUTOINCREMENT), agent, type, entity, op, rows_read, rows_written, duration_ms, result, ts (NOT NULL)
  -- D1 anonymous positional `?` params ONLY. No named (`?1`/`:name`) params.
