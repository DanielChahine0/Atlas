<objective>
Stand up the OAuth substrate for SPINE-04: the inbound Workers OAuth Provider front door (the owner authorizes once; the local daemon and each MCP client present access tokens), the outbound Google offline-refresh round-trip (least-privilege scopes, refresh token captured into Secrets Store), and the outbound GitHub App installation-token round-trip (RS256 JWT via jose → opaque per-run token). The inbound provider becomes the Atlas Worker default export, composed with the Wave-3 `scheduled()` dispatcher (00-03) and re-exporting the `AtlasCoordinator` DO. Provider credentials live in Cloudflare Secrets Store and are read async — never in `[vars]`, KV, the Vault, the Codex, or `audit_log`.

Purpose: Every outward-acting agent (Filer's `gmail.modify`, Herald's draft scope, Sundial's `calendar.events`, Envoy's GitHub App) inherits this auth plumbing. Getting least-privilege scopes, the `access_type=offline`+`prompt=consent`+S256 flags, and Secrets-Store-only credential storage right here means the 16 agents authorize correctly for free, and a leaked Vault/Codex export never hands an attacker the owner's Gmail.

Output: `apps/atlas/src/index.ts` rewritten as the `OAuthProvider` default export composed with the dispatcher; `oauth/google.ts` (authorize/exchange/refresh) and `oauth/github.ts` (App JWT + installation token) helpers; `auth/consent.ts` defaultHandler; the Wave-4 leg of the `apps/atlas/wrangler.jsonc` 3-way cross-wave handoff (ADD the `secrets_store_secrets` block for the three OAuth bindings while preserving the 00-01 base config + the 00-03 `services` NOOP binding); an `oauth.test.ts` proving the round-trip contracts; plus three owner-provisioning gates (GCP OAuth client + consent screen, GitHub App registration, Secrets Store entries) the human must complete before the live round-trip acceptance passes.
</objective>
