<objective>
Stand up the three remote MCP Workers and the outbound-only Obsidian bridge drain — the SPINE-04 redaction backstop and the SPINE-05 bridge half of the spine.

- **mcp-google** (stateless `createMcpHandler`): the Google MCP server façade with the server-side `Type/Security` body strip that removes 2FA codes / reset links / login URLs from tool output **regardless of scope** (defense-in-depth with `packages/security`), plus the `gmail.modify` least-privilege scope floor enforced server-side (403 on a token lacking it) with **no reachable** `messages.delete`/`threads.delete` path.
- **mcp-github** (stateful `McpAgent` + `OAuthProvider`): the GitHub MCP, fronted by the inbound OAuth provider; GitHub-App credentials never reach the client.
- **mcp-obsidian-bridge** (cloud side): `/bridge/poll` + `/bridge/ack`, both token-gated by `ATLAS_BRIDGE_TOKEN`, draining `vault_outbox` (written by Steward in 00-04) to the local daemon, which PATCHes the Obsidian Local REST API v3 at `https://127.0.0.1:27124`. The op→REST map has **only** PATCH/PUT/POST — Steward never DELETEs the Vault (Pillar 2).
- **daemon/** outbound-drain skeleton (the `drain.ts` long-poll loop + the launchd plist). The laptop has **zero inbound port**; the daemon authenticates outbound and pulls work.
- **Owner-provisioning gate tasks** (this is why the plan is `autonomous: false`): install the Obsidian Local REST API plugin, mint `ATLAS_BRIDGE_TOKEN` into the Secrets Store / `wrangler secret`, register the launchd plist, and prove with `lsof` that no inbound Atlas port exists.

Purpose: SPINE-04's redaction is the load-bearing third leg of "NEVER surface 2FA codes / reset links / login URLs" — a prompt instruction alone is not sufficient, so the server-side strip + its CI test land here. SPINE-05's outbound-only bridge is the only way Steward's projection reaches the Vault without ever opening an inbound port on the laptop.
Output: three deployable MCP Workers, a runnable daemon drain skeleton + launchd plist, and the scope/redaction/bridge tests that prove the security invariants.
</objective>
