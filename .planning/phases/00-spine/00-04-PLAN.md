<objective>
Build THE CRUX of the spine: the `StewardWriter` Durable Object (`getByName("vault")`) whose atomic dedup-check + counter-bump + ledger-insert run as ONE `DB.batch()` inside `blockConcurrencyWhile`, and the single `atlas-wire` consumer (`max_concurrency=1`, serial `for…of`). This is SPINE-02 (serialized single-consumer, replay ⇒ `meta.changes === 0`) and the consumer→DLQ wiring half of SPINE-05. The `packages/steward-core` package holds the reusable op→D1 critical-section logic + the op→Local-REST (`vault_outbox`) mapping. This plan adds the `queues.consumers` block to `apps/steward/wrangler.jsonc` and is the ONLY plan that touches that file.

Purpose: Steward is the SOLE Vault writer and the ONLY `atlas-wire` consumer (Pillar 1). Getting serialization + idempotency correct from day 0 is non-negotiable — Cloudflare Queues are at-least-once with best-effort ordering, so replays WILL happen (partial-batch failure, missed-cron catch-up, network blip after a server-side success). Retrofitting idempotency after counters exist means reconciling double-counts. The replay test is the single test that proves Pillar 5 end-to-end.
Output: A buildable `packages/steward-core` package; the `StewardWriter` DO + the single consumer + the Worker entry; the `apps/steward/wrangler.jsonc` consumers block (with `dead_letter_queue: atlas-wire-dlq`, NO invalid `retry_delay_secs` key); and the three mandatory tests (replay, serialize, malformed) green.
