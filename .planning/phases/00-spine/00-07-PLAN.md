<objective>
Build the two shared service packages every Phase-1 reasoning agent consumes from day one, completing SPINE-03 (the Codex exists, read-only, with the §11 sections) and standing up the model-access spine:

- `packages/codex` — a read-only reader of `codex.md` in Google Drive via `drive.readonly`, returning the seven §11 sections (identity, education, work, skills, projects, bios, socials) and caching the Codex text as an ephemeral `system` `TextBlockParam` (`cache_control:{type:"ephemeral", ttl:"1h"}`) so reuse is at 0.1x read cost. There is **no agent write path** — the package exposes only a read helper; the only mutation channel (the explicit "update my profile" flow) is out of Phase-0 scope and is NOT implemented here.
- `packages/model` — the `claudeFor(agent,env)` / `modelFor(agent,env)` factory. Every Claude call routes through the dedicated AI Gateway Anthropic endpoint (never `api.anthropic.com` directly); per-agent model tiering is read from config (KV `model:<codename>` override → `[vars]` `MODEL_*` default), not hardcoded; a non-2xx Gateway response raises a Flagger flag via `flag(env,"P3",…)`, emitting the canonical `op:"upsert"`/`entity:"flag"` full-flag-record Wire event toward Flagger.

Purpose: Filer, Herald, Forge, Compass, Archivist (Phase 1+) all read the Codex for context and call Claude through this one factory. Establishing both as shared packages now means the 16 agents inherit one canonical reader and one canonical model entrypoint — tiering becomes a config flip, and the read-only Codex invariant is enforced in code, not by convention.
Output: Two buildable, typechecked packages with passing tests — a read-only Codex reader and the AI-Gateway model factory. Phase 0 stands these up; no live Claude call is required for Phase-0 completion (the gateway + Anthropic key are owner-provisioned in 00-06; models are first invoked in Phase 1).
</objective>
