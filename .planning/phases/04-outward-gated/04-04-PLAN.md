<objective>
Extend the Phase-3 local macOS daemon with a second outbound channel — the browser-action runner — that drains `browser_action_outbox` work items and executes them locally in the owner's already-logged-in Chromium profile via Playwright (D4-00/D4-05: "cloud-brain + local-hands"). This is the only place a credentialed browser action runs; the cloud never holds a session.

Purpose: §12 no-credential-storage is a MECHANICAL invariant, not a promise — a cloud headless browser literally cannot hold the owner's LinkedIn/X/event-site login without becoming a credential store. The daemon authenticates OUTBOUND (Bearer token, no inbound port), polls, drains serially, executes locally, and acks the outcome. Hard stops (captcha, payment) are detected and handed back; nothing auto-proceeds past them.

Output: `daemon/src/browser-drain.ts` (poll/drain/ack, copied from drain.ts) + `daemon/src/browser-runner.ts` (Playwright executor, injected as a testable dep) + Node unit tests against mock pages + main.ts wiring.

This plan is `autonomous: false` — Playwright/Chromium install + the owner's profile-login are go-live owner actions (the code + mock tests run without them).
</objective>
