It owns the `gate_pending` D1 schema, the constant-time token, the open/decide/sweep lifecycle, the dual `audit_log` rows (§8), the ntfy push builder, **and — critically — the actual ntfy push SEND inside `openGate()` (the D4-01 approval surface that delivers the confirm link to the owner)**, and the server-rendered confirm-page HTML. Purpose: One enforcement point for Pillar 2 (suggest-don't-destroy). Fail-safe is implemented ONCE here: decline → no action; timeout → expired with no action; error → deny. Drift between per-agent inline gates is the most dangerous fail-open trap (RESEARCH.md "Don't Hand-Roll" key insight) — this primitive eliminates it. The push-SEND lives here too (the single chokepoint per D4-04): every caller (Usher, Envoy, Sundial, any future delete) gets confirm-link delivery for free and no agent can forget it.

Output: `packages/gate/` (a new workspace package, NOT a Worker) + `migrations/0007_gate.sql` + the named Wave 0 test files.
