<objective>
Build the shared `packages/gate` confirmation-gate primitive (D4-04) — the heart of Phase 4 and the roadmap's "gate-UX maturity." It owns the `gate_pending` D1 schema, the constant-time token, the open/decide/sweep lifecycle, the dual `audit_log` rows (§8), the ntfy push builder, and the server-rendered confirm-page HTML. It also ships `migrations/0007_gate.sql` (both `gate_pending` and `browser_action_outbox`) and all Wave 0 test stubs so Usher, Envoy, the `apps/gate` Worker, the daemon, and the Sundial retrofit can consume it.

Purpose: One enforcement point for Pillar 2 (suggest-don't-destroy). Fail-safe is implemented ONCE here: decline → no action; timeout → expired with no action; error → deny. Drift between per-agent inline gates is the most dangerous fail-open trap (RESEARCH.md "Don't Hand-Roll" key insight) — this primitive eliminates it.

Output: `packages/gate/` (a new workspace package, NOT a Worker) + `migrations/0007_gate.sql` + the named Wave 0 test files.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller (Usher/Envoy/Sundial) → packages/gate | trusted in-process call; the gate must still enforce fail-safe + audit regardless of caller |
| artifact payload → confirm-page HTML | agent-drafted text may transitively contain email-derived content; must be redacted before render |
| gate token (in confirm link) → gate_pending lookup | untrusted token from the open internet crosses here; constant-time compare + hashed storage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | decideGate fail-open on error | mitigate | D1 batch (status transition + terminal audit row) commits BEFORE any side effect; on batch throw the function rethrows → caller 5xx → no action (Task 3 fail-closed test) |
| T-04-02 | Spoofing | confirm token forgery/guess | mitigate | 32-byte random token; only SHA-256 hash stored (token_hash); constant-time timingSafeEqual; lookup gated to status='pending' (Task 2/3) |
| T-04-03 | Tampering | token replay (re-use confirm link) | mitigate | decideGate UPDATE has `AND status='pending'`; a second decide matches 0 rows → no-op (Task 3 double-decide test) |
| T-04-04 | Information Disclosure | 2FA code / reset link / login URL in confirm page or push | mitigate (HIGH) | redact() from @atlas/security applied to artifact + push title/body before egress; render.test.ts security invariant blocks (Task 2) |
| T-04-05 | Information Disclosure | credential/secret stored in gate_pending or browser_action_outbox | mitigate | 0007 schema comment forbids it; fields/artifact carry only Codex field values; token never stored plaintext (Task 1) |
| T-04-06 | Repudiation | gated action with no audit trail | mitigate | dual audit_log rows (pending + terminal) sharing target; reconstructable by `WHERE target=? AND gated=1 ORDER BY ts` (Task 3) |
| T-04-07 | Elevation of Privilege | duplicate gate per caller key (double-count) | mitigate | UNIQUE idx_gate_idem_key; openGate returns existing row on conflict (Task 1/3) |
| T-04-SC | Tampering | new npm install (ulid only if not already present) | mitigate | Prefer the project's existing ulid usage; no new package unless RESEARCH Package Legitimacy Audit covers it (playwright/agents/mcp-sdk all [OK]). No [ASSUMED]/[SUS] package installed in this plan |
</threat_model>
