## Task 1: Forge.createTask (INT-BLOCKER-1 / WEEKLY-01)

### What was built

Added `async createTask(task: CreateTaskInput, opts: CreateTaskOpts): Promise<{id:string}|null>` to `class Forge extends WorkerEntrypoint<Env>` in `apps/forge/src/index.ts`.

The method:
1. Derives `id = taskIdFor(opts.idempotencyKey)` — Headhunter tasks carry `thread: null`, so `dedupeKey(thread, …)` does not apply; the structured window key IS the stable per-window identity
2. Runs `upsertTask(db, input)` inside the `FORGE_LOCK` DO addressed by `opts.runId` (falls back to identity runner when absent — same pattern as `morning()`)
3. Calls `send(this.env, buildTaskEvent(id, action, mergeKey?))` OUTSIDE the lock, mirroring `runMorning`
4. Returns `{id}` for `inserted | merged`; returns `null` for `noop` (owner-locked)

Zero duplicated dedupe logic — entire implementation delegates to the existing `taskIdFor` / `upsertTask` / `buildTaskEvent` / `contentHashOf` / `FORGE_LOCK` / `send` pipeline.

Also exported `CreateTaskInput` and `CreateTaskOpts` types so Headhunter's typed `FORGE` binding can satisfy the structural contract without inference.

### Tests added (create-task.test.ts)

- **Test 1 (binding symmetry):** `typeof new Forge(ctx, env).createTask === "function"` — the INT-BLOCKER-1 regression guard; fires in CI before the TypeError fires at runtime
- **Test 2 (real D1 task + Wire event):** real insert with exact Headhunter shape; asserts `{id}` return, D1 row readable by `SELECT WHERE id=?`, canonical `buildTaskEvent(id,"inserted")` event passes `WireEvent.parse`
- **Test 3 (replay no-op):** second call with same `idempotencyKey` produces no duplicate row (`COUNT(dedupe_key) === 1`); replay of insert event through `applyEvent` returns `{applied:false}`; counter moved by exactly +1 (mirrors wire.test.ts:32-43)
- **Test 4 (null return):** fresh insert returns non-null id; pre-inserted `locked_by_owner=1` row causes createTask to return `null`

## Task 2: Shared atlas-db database_id in 5 wranglers (INT-WARN-1 / CORE-01)

Added `"database_id": "e7fee76c-2e3d-486e-8a8a-fd1aec6a5af3"` to the `d1_databases` entry in each of:

- `apps/filer/wrangler.jsonc`
- `apps/herald/wrangler.jsonc`
- `apps/forge/wrangler.jsonc`
- `apps/sundial/wrangler.jsonc`
- `apps/compass/wrangler.jsonc`

Placed immediately after `"database_name": "atlas-db"` and before `"migrations_dir"`, matching the ordering in `apps/steward/wrangler.jsonc`. Without this id, `wrangler deploy` would silently create or bind a Worker-isolated D1 rather than the shared `atlas-db`, splitting task storage so Sundial/Compass could not read Forge's tasks.
